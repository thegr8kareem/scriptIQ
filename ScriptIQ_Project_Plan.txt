1. Project Overview
ScriptIQ is a fully client-side academic integrity analyser that combines TF-IDF similarity scoring, LCS-based TextDiff visualisation, and a D3.js plagiarism network graph — all running in the browser with no server installation. This document defines every language, library, and tool required to build ScriptIQ, and provides a detailed day-by-day 3-week milestone plan for the team.
2. Languages, Libraries & Tools
ScriptIQ is built entirely with browser-native and JavaScript-ecosystem technologies. No backend server is required — all computation runs in the client. Below is a complete breakdown by layer.

2.4  Core Algorithms — Implemented in Pure JavaScript
Both primary algorithms are written from scratch in vanilla JavaScript. No external library handles them — this is a core academic contribution of the project.
TF-IDF + Cosine Similarity (Similarity Detection)
TF-IDF (Term Frequency–Inverse Document Frequency) represents each document as a weighted vector
Cosine Similarity computes the angle between two document vectors — 1.0 = identical, 0.0 = no overlap
Steps to implement:
Tokenise: split text into lowercase words, strip punctuation
Remove stopwords: filter common words (the, a, is, of…) using a stopword list
Compute TF for each term in each document
Compute IDF across the full corpus (all uploaded documents)
Multiply TF × IDF to get each document's weighted vector
Compute dot product and vector magnitudes to get cosine score
Longest Common Subsequence — LCS (TextDiff View)
LCS finds the longest sequence of lines that appear in the same order in both documents
Used to build the side-by-side diff showing additions (green), deletions (red), and unchanged text
Steps to implement:
Split both documents into lines (or sentences for finer granularity)
Build the standard DP table: lcs[i][j] = length of LCS of first i and j lines
Backtrack through the DP table to label each line as MATCH, ADD, or DELETE
Render the labelled lines side-by-side in two scrolled panels with CSS colour coding

6. Practical Tips
Start with a single hardcoded pair of text strings before wiring up PDF.js — confirm your algorithms work first
For TF-IDF, expand the stopword list to include common Ghanaian academic phrases that appear in every submission ('University', 'KNUST', 'Department', 'student number')
LCS is O(m×n) memory and time — for very long documents, chunk at the paragraph level rather than line level to keep it fast
D3 force simulations need a cooldown period — call simulation.alphaDecay(0.05) for smoother initial layout
The HuggingFace free API cold-starts — first request after inactivity takes ~15 seconds; show a loading message
Test early and often on real KNUST submission PDFs — the text extraction quality determines everything downstream
Use browser DevTools Performance tab to identify any main-thread blocking before moving heavy work to Web Workers
